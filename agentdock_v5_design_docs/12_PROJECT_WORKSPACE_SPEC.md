# Project Workspace Specification

## 1. Purpose

The project workspace gives agents a shared filesystem protocol for coordination. It replaces invisible shared chat assumptions with durable files.

## 2. `.agentdock` directory

Project-local AgentDock config and generated runtime files.

```txt
.agentdock/
├─ config.yml
├─ config.runtime
├─ prompts/
│  ├─ orchestrator.md
│  ├─ backend.md
│  └─ qa.md
├─ generated/
│  ├─ boot-orchestrator.md
│  ├─ boot-backend.md
│  └─ boot-qa.md
└─ state/
   ├─ events.log
   ├─ doctor.log
   ├─ last-start.log
   └─ panes.env
```

## 3. `.agent-work` directory

Shared agent work state.

```txt
.agent-work/
├─ 07_JOBS/
│  ├─ CURRENT.md
│  └─ JOB-YYMMDDHHMMSS/
├─ 08_DECISIONS/
├─ 09_HANDOFFS/
├─ 10_REPORTS/
├─ 11_ARCHIVE/
├─ 12_INBOX/
│  └─ <role-id>/
├─ 13_OUTBOX/
│  └─ <role-id>/
├─ 14_SHARED_CONTEXT/
│  └─ PROJECT_CONTEXT.md
└─ LOCKS.md
```

## 4. Job structure

Generated by:

```bash
agentdock task "..."
```

```txt
.agent-work/07_JOBS/JOB-YYMMDDHHMMSS/
├─ README.md
├─ TASKS/
├─ LOGS/
├─ REPORTS/
├─ HANDOFFS/
└─ OUTPUTS/
```

`README.md` template:

```md
# JOB-YYMMDDHHMMSS

## User request
<text>

## Created
<timestamp>

## Status
new

## Assigned orchestrator
<role-id>

## Expected flow
1. Orchestrator reads request.
2. Orchestrator breaks into task cards.
3. Workers execute accepted task cards.
4. QA verifies.
5. Reviewer writes final report.
```

## 5. Inbox/outbox

Each role has its own inbox/outbox:

```txt
.agent-work/12_INBOX/backend/
.agent-work/13_OUTBOX/backend/
```

Message file naming:

```txt
MSG-YYMMDDHHMMSS-from-<sender>.md
```

## 6. Reports

Each role writes reports to:

```txt
.agent-work/10_REPORTS/<role-id>/
```

Report file naming:

```txt
REPORT-YYMMDDHHMMSS.md
```

## 7. Handoffs

Handoff path:

```txt
.agent-work/09_HANDOFFS/<from-role>__to__<to-role>__YYMMDDHHMMSS.md
```

## 8. Decisions

Decision path:

```txt
.agent-work/08_DECISIONS/ADR-YYMMDDHHMMSS-<slug>.md
```

## 9. Locks

Soft lock file:

```txt
.agent-work/LOCKS.md
```

Format:

```md
# AgentDock Locks

## Active locks

| Role | Files | Reason | Since |
|---|---|---|---|
| backend | server/api/*.ts | implementing webhook | 26051810:30:00 |
```

Agents are instructed to check this file before editing. MVP does not enforce OS-level locks.

## 10. Shared context

`PROJECT_CONTEXT.md` should contain:

- project purpose;
- stack;
- key commands;
- test commands;
- deployment notes;
- known risks.

AgentDock can generate an initial skeleton during init.
