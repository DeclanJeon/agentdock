# Design to Development Flow

## 목표

디자인 산출물을 개발 가능한 명세로 넘기는 과정이다.

```txt
PM → Design → Architecture → Development → QA
```

## Design Team이 제공해야 할 것

- 화면 목적
- 사용자 흐름
- 상태별 UI
- 반응형 기준
- 컴포넌트 목록
- 에러/빈 상태
- 접근성 기준

## Development Team이 Design에 요청할 수 있는 것

- 컴포넌트 상태 누락
- API 응답 상태별 화면
- 모바일 breakpoint
- 텍스트 길이 overflow 기준
- 로딩/실패 상태

## Handoff 기준

디자인은 “예쁘게”가 아니라 “구현 가능하게” 넘긴다.
