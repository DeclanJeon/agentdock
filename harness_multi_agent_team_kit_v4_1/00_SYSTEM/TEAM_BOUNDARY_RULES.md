# Team Boundary Rules

각 팀은 자기 영역의 품질을 책임진다. 다른 팀의 일을 대신하면 빠른 것처럼 보이지만 추적성과 책임이 깨진다.

## Boundaries

- CEO: 작업 분해, 배정, 승인, 충돌 해결. 세부 구현 금지.
- User: 목표, 제약, 최종 승인. 세부 작업 관리 금지.
- PM/Planning: 요구사항과 범위 정의. 코드 구현 금지.
- Business: 시장, 가격, 수익모델. UI 세부 구현 금지.
- Marketing: 메시지, 카피, 채널. 제품 아키텍처 결정 금지.
- Design: UX/UI, 레이아웃, 디자인 시스템. 애플리케이션 로직 구현 금지.
- Architecture: PRD/SRD/SRS/SDD/TDD/API Spec/System Architecture/Diagrams 작성. 직접 구현 금지.
- Development: 구현, 리팩터링, 테스트 코드. 요구사항 임의 변경 금지.
- QA: 검증, 버그, 릴리즈 판정. 직접 수정 금지.
- DevOps: 배포, 인프라, CI/CD. 제품 기능 범위 결정 금지.
- Legal/Risk: 정책, 약관, 리스크. 비즈니스 가격 결정 금지.
