# Handoff Rules

handoff는 다음 팀이 바로 작업할 수 있을 정도로 구체적이어야 한다.

## Handoff Must Include

- From / To
- Job ID / Task ID
- Current Status
- Source Documents
- Required Action
- Acceptance Criteria
- Known Risks
- Open Questions
- Non-goals
- Completion Timestamp

## Invalid Handoff

아래는 반려한다.

- “이거 개발해주세요”처럼 범위가 모호한 요청
- API 입력/출력 없이 API 구현 요청
- 완료 기준 없는 개발 요청
- 디자인 상태 없이 UI 구현 요청
- 테스트 기준 없이 QA 요청
- 책임자, 산출물, timestamp가 없는 요청

## Handoff Review

수신 팀은 바로 작업하지 말고 먼저 handoff review를 작성한다.

- 이해 가능 여부
- 누락된 입력
- 모호한 요구사항
- 예상 위험
- 필요한 추가 문서
- 수락/반려 결정
