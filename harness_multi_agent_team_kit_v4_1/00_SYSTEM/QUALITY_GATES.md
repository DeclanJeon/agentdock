# Quality Gates

## Gate 0: 업무 정의 완료

- [ ] 목적이 한 문장으로 설명된다.
- [ ] 대상 사용자가 정의되어 있다.
- [ ] 성공 기준이 측정 가능하다.
- [ ] 하지 않을 일이 정의되어 있다.
- [ ] 담당 팀과 수신 팀이 명확하다.

## Gate 1: 기획 승인

- [ ] PRD가 있다.
- [ ] 유저스토리가 있다.
- [ ] 우선순위가 있다.
- [ ] 엣지케이스가 있다.
- [ ] CEO가 범위를 승인했다.

## Gate 2: 설계 승인

- [ ] 시스템 경계가 있다.
- [ ] 데이터 모델이 있다.
- [ ] API 계약이 있다.
- [ ] 실패/복구 전략이 있다.
- [ ] 보안/권한 검토가 있다.

## Gate 3: 디자인 승인

- [ ] 사용자 흐름이 있다.
- [ ] 화면별 목적이 있다.
- [ ] 디자인 시스템 기준이 있다.
- [ ] 반응형 기준이 있다.
- [ ] 접근성 기준이 있다.

## Gate 4: 개발 완료

- [ ] 요구사항을 충족한다.
- [ ] 주요 테스트가 통과한다.
- [ ] lint/typecheck가 통과한다.
- [ ] 변경 범위가 설명된다.
- [ ] known issue가 기록되어 있다.

## Gate 5: QA 승인

- [ ] happy path 통과
- [ ] failure path 통과
- [ ] 브라우저/디바이스 기준 통과
- [ ] 회귀 테스트 통과
- [ ] QA가 승인 또는 반려 사유를 남겼다.

## Gate 6: 릴리즈 승인

- [ ] 릴리즈 노트가 있다.
- [ ] 롤백 계획이 있다.
- [ ] 모니터링 지표가 있다.
- [ ] 사용자 공지/마케팅 메시지가 준비됐다.
- [ ] CEO가 최종 승인했다.
